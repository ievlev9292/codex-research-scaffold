# Initialize or rebind a project

Read AGENTS.md. Establish the scientific question and authorized scope from the current request and supplied material. Use existing records when resuming; initialize a new project without inventing findings.

1. Run tools/initialize.py --root PROJECT audit using the selected Python executable. Supply explicit local tool bindings and host policy when discovery is insufficient; configured/user-approved executable paths take precedence over PATH discovery. The current user's laptop permits one numerical job at a time; record that host-specific preference when initializing it. Other hosts receive justified limits from their resources. Keep headroom for concurrent user applications.
2. Run the bounded Python capability probe when relevant. Record imports and actual small numerical/symbolic/table/plot results separately from installed-version metadata. Inspect available Python baseline packages, Wolfram launcher/kernel/license, LaTeX/bibliography/fonts/packages and PDF tools. A file's presence is not a successful capability test.
3. Inspect plugin and standalone-skill identity, actual location, provenance and activation separately. A cache directory proves only a cached copy. Compare installed versions with authoritative latest stable releases and compatible targets; check dates and URLs belong in host audit records. Unknown provenance/version/compatibility remains unknown. Preserve pins and local modifications. This online comparison is an agent step, not implied by local inventory.
4. Execute a tiny headless .wl check and minimal TeX/bibliography/PDF checks using exact configured executables and host invocation rules. For MiKTeX use --disable-installer; no automatic package installation. Keep probes in a unique project tmp/ folder, and record actual results with initialize.py record-check. Missing optional capabilities do not block unrelated work.
5. Inventory provided sources and reports, including useful titles/abstracts/contents where accessible. Apply [selective indexing](retrieval.md). Inventory, extraction, reading and scientific verification remain different states. Register relevant existing reports and verified locators; expose ambiguous aliases and unknown page mappings.
6. Check supplied arXiv versions as described below. This requires an actual online comparison; inventory alone is not a version check.
7. State the question, resource choices, coverage gaps and prioritized environment recommendations in a concise initialization summary. Set PROJECT_HANDOFF.md to the next useful action or start an authorized research run.

Use initialize.py --help and its subcommand help for exact receipt/binding formats. Store local paths in config/host.local.json, never in portable defaults. Record release evidence with record-release; do not claim a full version audit from inventory alone.

An audit permits inspection and capability checks. Installations, updates, removals, licensing/sign-in changes and global settings follow explicit user authorization. Refresh relevant facts on meaningful host/environment changes or request; ordinary runs reuse the audit and check current available resources.

## Supplied arXiv versions

During source inspection, identify arXiv IDs and the versions actually supplied, using title-page/version text or other reliable local evidence. Do not infer a local version from an unversioned filename/link, file timestamp, or a citation to another paper. Notebook-content restrictions still apply. Deduplicate online requests by ID; compare each supplied copy separately with the official arXiv record and submission history. A different arXiv ID is not automatically a revision of the same work.

Record a compact arxiv_check object in the existing source catalogue via catalog.py set-metadata. Include arxiv_id, source_sha256, local_version (integer or null), local_evidence, latest_version (integer or null), latest_date, official_url, checked_at and status. Status is current only for an identified local version equal to the verified latest version; older for a lower version; local_version_unknown when local evidence is inconclusive; online_check_unavailable when the online record cannot be verified. Use status unverified with a reason for conflicting versions/identities, including a purported local version higher than the verified latest version. Reuse a same-initialization online result for duplicate IDs, not a guessed local-version assignment. Recheck on changed source hashes or a later requested initialization; do not present an old dated comparison as current.

Use the official abs page for the identified ID, inspecting its submission history rather than treating a pinned v1 page as latest. Source notes identify the version actually used for research. Preserve supplied originals; separately catalogue any acquired revision and its relation to them. Summarize older copies and unresolved checks in the existing initialization summary. Failed access does not stop unrelated work. This is version discovery, not full paper review, scientific verification or automatic replacement; no separate audit dossier is required.
